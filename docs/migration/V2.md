# Plutus execution budgets now use the chain cost model

This migration note targets the 2.0 release candidate.

Pass the current protocol parameters' cost-model array for the script's language. All deployed builtins and every CEK machine step use that array. V4 uses the V3 table instead of the reference model. V1 and V2 scripts take their own language's array once V3 and T6 land.

```csharp
// plutusV3Costs: the PlutusV3 cost model of the current protocol parameters.
static EvaluationResult Evaluate(byte[] flatScript, IReadOnlyList<byte[]> argumentsCbor, IReadOnlyList<long> plutusV3Costs) =>
    Evaluator.EvaluateScript(flatScript, argumentsCbor, plutusV3Costs, plutusVersion: 3);
// Before 2.0, builtins 87–100 and every machine step were priced from built-in defaults, whatever array was passed.
```

A short array no longer throws: missing coefficients are treated as `long.MaxValue`; extra coefficients beyond the deployed table are ignored. Do not use a truncated array to estimate fees. Division-family pricing (including remainder), subtracted-size and literal-in-y models, and the order of saturating arithmetic now follow the ledger. `ExBudget` addition and subtraction saturate at the signed 64-bit bounds; reported units saturate instead of wrapping to zero.

Six `DefaultFunction` values now match the upstream Flat encoding. Names have not changed. If you stored the numeric enum values, remap them as follows; do not remap already-correct upstream Flat bytes.

| Builtin suffix | G1 old → new | G2 old → new |
|---|---:|---:|
| `Compress` | 59 → 58 | 66 → 65 |
| `Uncompress` | 60 → 59 | 67 → 66 |
| `HashToGroup` | 58 → 60 | 65 → 67 |
