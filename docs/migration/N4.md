# Era values in state queries

## The helpers query in the ledger's era

`GetTipAsync`, `GetCurrentProtocolParamsAsync`, `GetUtxosByAddressAsync` and
`GetUtxosByTxInAsync` now ask the node for its ledger's era in the snapshot they
acquire, then send their query for that era, from Shelley on. Before, they always
sent a Conway query, so on a ledger in any other era they threw the era-mismatch
error, and after the next hard fork they would have thrown it on every node.
Each call makes one more round trip in the same snapshot. `GetCurrentEraAsync`
is unchanged.

When the ledger is in Byron, or in an era this version does not know, the four
helpers throw `InvalidOperationException` before they send their query, for
example `The node's ledger is in era 0, which these helpers cannot query.`, and
release the snapshot. On a ledger before Babbage the parameter helper can throw
"Failed to deserialize response" instead of the era mismatch. All of these are
`InvalidOperationException`, as the era mismatch was.

## The query builders take the era

The era-specific builders of `RawQueries` take the ledger era, Shelley or later,
as an `Era` (`Chrysalis.Codec.Types.Cardano.Core`); read it with
`RawQueries.GetCurrentEra` in the same acquired snapshot. It is neither the
negotiated version (`NodeClient.NegotiatedVersion`) nor a transaction's era:
`EraTx.Era` stays the era the transaction is encoded in, such as
`(int)Era.Conway` for every transaction Chrysalis builds.

| Before | After |
|---|---|
| `GetTip` (a property) | `GetTip(Era era)` |
| `GetCurrentProtocolParams` (a property) | `GetCurrentProtocolParams(Era era)` |
| `CreateBlockQuery(IQueryReq query)` | `CreateBlockQuery(IQueryReq query, Era era)` |
| `GetUtxoByAddress(addresses)` | `GetUtxoByAddress(addresses, Era era)` |
| `GetUtxoByTxIns(txIns)` | `GetUtxoByTxIns(txIns, Era era)` |

```csharp
Result answer = await query.QueryAsync(RawQueries.GetCurrentEra, token);
Era era = (Era)CborSerializer.Deserialize<CurrentEraQueryResponse>(answer.QueryResult.Raw).CurrentEra;
Result tip = await query.QueryAsync(RawQueries.GetTip(era), token);
```

Before the cast, refuse Byron (0) and any value `Era` does not define, as the
helpers do: on a Byron ledger the node drops the connection at such a query,
and an era this version does not know would be read with another era's types.
