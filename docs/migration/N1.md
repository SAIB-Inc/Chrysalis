# Local state query results

## The result is the node's inline item

`Result.QueryResult`, in `Chrysalis.Network.Cbor.LocalStateQuery.Messages`, changes
type from `CborEncodedValue` to `CborAny`. The node sends a query's result inline
(`[4, result]`); the old type expected a tag-24 byte string, so it failed on every
real reply. Rebuild code that names the property, the record's constructor or its
deconstructor.

Before:

```csharp
Result result = await query.QueryAsync(request, token);
ReadOnlyMemory<byte> bytes = result.QueryResult.Value;
```

After:

```csharp
Result result = await query.QueryAsync(request, token);
ReadOnlyMemory<byte> bytes = result.QueryResult.Raw;
MyAnswer answer = result.QueryResult.To<MyAnswer>();
```

`Raw` is the result item exactly as the node sent it. An era-specific query's
result is `[value]`, or `[queryEra, ledgerEra]` when the node's ledger is in
another era; each era is `[index, name]`.

## Helper errors

`GetTipAsync`, `GetCurrentEraAsync`, `GetCurrentProtocolParamsAsync`,
`GetUtxosByAddressAsync` and `GetUtxosByTxInAsync` now decode the node's answers;
before, they failed on every real node with a CBOR decoding exception. When the
node's ledger is in another era than the query, the four era-specific helpers (all
but `GetCurrentEraAsync`) throw `InvalidOperationException` naming both eras. A
result that cannot be decoded is also an `InvalidOperationException`, with the
decoder's `CborDecodeException` as `InnerException`. Code that caught a decoding
exception around these calls catches `InvalidOperationException` instead. A
reply that is not a well-formed result message still throws `CborDecodeException`
from `QueryAsync`.

`GetTipAsync` returns the ledger tip's point. Its `BlockNumber` is null, because
the ledger-tip query reports no block number.
