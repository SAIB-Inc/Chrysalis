# Plutus scripts must return unit

Both `Evaluator.EvaluateScript` overloads now throw `InvalidReturnValueException : EvaluationException` if a script other than Plutus V1 or V2 returns anything but built-in unit. Transaction evaluation through `TxBuilder` preserves that cause as the inner exception of its existing `InvalidOperationException`. `EvaluationException` is no longer sealed; existing catches still work.

## Before

```csharp
var result = Evaluator.EvaluateScript(v3ScriptReturningOne, arguments); // Returned a budget.
```

## After

```csharp
var result = Evaluator.EvaluateScript(v3ScriptReturningOne, arguments); // Throws InvalidReturnValueException.
```

Change a successful V3 validator to return built-in unit (`(con unit ())` in UPLC), not an integer, Boolean, or `Data` value. The default `plutusVersion` is `3`, so pass the actual version (`plutusVersion: 1` or `plutusVersion: 2`) for legacy scripts; otherwise this check treats them as V3. The V1/V2 result rule and raw `Evaluator.EvaluateTerm` are unchanged.
