# Script evaluation takes the language and the protocol version

`Evaluator.EvaluateScript` now requires `plutusVersion` (1, 2 or 3) and the
major `protocolVersion`, before `costModel`. Pass the version of the protocol
parameters you build against. `Evaluator.LatestProtocolVersion` is 11 in this
release. A newer protocol version this release does not define throws
`NotSupportedException`. An unknown language or negative protocol version
throws `ArgumentOutOfRangeException`.

A language not yet introduced, a builtin unavailable at the requested version,
or `constr` or `case` in a 1.0.0 program throws `InvalidOperationException`.
An unavailable Plutus Core version or evaluating `case` on a builtin constant
before protocol version 11 throws `EvaluationException`. Other malformed Flat
inputs keep their existing exceptions. PV11 is checked against recorded node
results; earlier versions are checked against the node's pinned Plutus sources.

Plutus V1 and V2 scripts run again when you pass the cost-model array of their
language. Only Plutus V3 at PV11 can omit the array. Transaction evaluation still
refuses V1 and V2 until it can build their script contexts. `EvaluateTx` takes an
optional `protocolVersion`, defaulting to `Evaluator.LatestProtocolVersion`.
Rebuild callers and update delegates bound to the old five-parameter signature.

## Before

    var result = Evaluator.EvaluateScript(script, arguments, plutusV3Costs);

## After

    var result = Evaluator.EvaluateScript(script, arguments, plutusVersion: 3, protocolVersion: 11, plutusV3Costs);

An old call like `EvaluateScript(script, arguments, default, 3)` still compiles,
but now interprets `default` as language 0 and throws `ArgumentOutOfRangeException`.
Name both versions to avoid it.

In Plutus V1 and V2, `consByteString` takes its integer modulo 256. String costs
count Unicode code points before PV11 and in `EvaluateTerm`, and UTF-8 bytes
divided by four from PV11. The raw `FlatDecoder.DecodeProgram` rejects `constr` and `case` in
1.0.0 programs and unknown builtin tags. Version parts and variable indices above
`int.MaxValue` saturate at `int.MaxValue` instead of wrapping.
