# CBOR lists

`CborList<T>` replaces `ICborMaybeIndefList<T>` and its four concrete list types.
Enumerate the property itself: `body.Inputs.GetValue()` and the old concrete list’s `.Value` both become `body.Inputs`.
A required list is a value type; an optional list is `CborList<T>?`. Unwrap an optional list with a pattern such as `if (body.Collateral is { } collateral)`.

Replace `new CborDefList<T>(x)` or `CborDefList<T>.Create(x)` with `CborList.Create(x)`.
Use `isIndefinite: true` for the former indefinite variants, and `hasSetTag: true` for the former `WithTag` variants.
Use `Count` for the item count. Replace type patterns on the old four types with `IsIndefinite` and `HasSetTag` checks.

Fresh lists have `Raw.IsEmpty == true`. Use `CborSerializer.Serialize(list)` to obtain bytes.
`default(CborList<T>)` has count zero and enumerates no items, but serializing it throws `CborValidationException`. To write an empty list, use `CborList.Create<T>([])`.
List equality and hashing use the backing memory slice or item array, not the contents. An enclosing record’s `==` follows this equality for its list members. Compare contents with `SequenceEqual`.
The existing primitive item codec still requires values: `CborList<int?>` supports non-null integers but does not encode or decode null items.

Find remaining calls with `rg '\.GetValue\(\)'`. Only list calls change; other `GetValue()` methods, such as the encoded-byte accessor on a script reference, are unaffected.
