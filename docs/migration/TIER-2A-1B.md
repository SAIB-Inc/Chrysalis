# Tier 2a-1b: Value-type `Address` and `CborEncodedValue`

`Chrysalis.Codec.Types.Cardano.Core.Common.Address` and `Chrysalis.Codec.Types.CborEncodedValue` are now 32-byte `readonly partial record struct` value types instead of `partial record` reference classes.

- **Nullable type change:** `CborEncodedValue?` (including `PostAlonzoTransactionOutput.ScriptRef`) and `Address?` are now `Nullable<T>` value types rather than nullable reference types.
  - Replace `if (output.ScriptRef is not null) { ... output.ScriptRef.GetValue() ... }` or `.Deserialize<T>()` with pattern unwrapping: `if (output.ScriptRef is { } scriptRef) { ... scriptRef.GetValue() ... }`.
  - Use `CborEncodedValue?` / `Address?` (with `?`) on any `[CborNullable]` property; `[CborNullable]` on non-nullable struct properties is not supported because `default(CborEncodedValue)` represents a present empty payload (`D8 18 40`), not CBOR null (`F6`).
  - Generic `CborSerializer.Deserialize<Address?>` and `Deserialize<CborEncodedValue?>` (both overloads) continue to work on valid CBOR bytes.
- **Eager `[CborMap]` explicit CBOR null alignment:** Eager `[CborMap]` classes (including `CostMdls`) now decode an explicit CBOR null (`0xF6`/`0xF7`) to `null` for CLR-nullable (`T?`) properties, matching lazy `[CborMap]` structs.
- **Constructors preserved; positional/mutable record members removed:** `new Address(ReadOnlyMemory<byte>)` (borrows input, `Raw = default`), `new CborEncodedValue(ReadOnlyMemory<byte>)` (borrows input, `Raw = default`), `Address.Create(...)` (encodes owned copy), and `CborEncodedValue.Create(...)` (encodes owned `#6.24(bstr)` copy) continue to work. The following former positional/mutable class members are removed: named `Value:` constructor argument, positional `Deconstruct` (`addr.Deconstruct(out var bytes)` -> `var bytes = addr.Value`), `Value` `init` (`with { Value = ... }`), and settable `Raw`/`ConstrIndex`/`IsIndefinite` (`ConstrIndex` is now fixed `0`, `IsIndefinite` is fixed `false`).
- **`default` & `#6.24` serialization contract:** `default(Address)` has empty `Value`/`Raw` and writes an empty CBOR byte string (`0x40`). `default(CborEncodedValue)` has empty `Value`/`Raw` and writes `#6.24(h'')` (`D8 18 40`) consistently across `CborEncodedValue.Write`, `CborEncodedValue.Create`, `CborSerializer.Serialize`/`GetEncodedLength`, `CborMap`/`CborList`, and generated fields (decoded instances with non-empty `Raw` still preserve `Raw` verbatim on direct `Write`/`Serialize`).
- **Equality and borrowed slices:** Equality and `GetHashCode` use synthesized `ReadOnlyMemory<byte>` handle equality on `Value` and `Raw` (O(1), matching `CborList<T>` and `CborMap<TKey, TValue>`). Compare byte content with `a.Value.Span.SequenceEqual(b.Value.Span)`. Definite decoded byte strings borrow the input buffer; call `.Value.ToArray()` or `.GetValue()` to retain bytes independently (indefinite `0x5F` byte strings remain owned copies).
