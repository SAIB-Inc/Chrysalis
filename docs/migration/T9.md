# T9: provider cancellation and errors

Rebuild binaries that call or implement `ICardanoDataProvider`, including callers of
concrete providers and UTxO RPC. Ordinary source calls still compile: the token is optional.
UTxO RPC's five no-token overloads for the interface methods were removed; use the
corresponding token-taking methods, including when binding delegates or using reflection.

## Custom providers

Before:

```csharp
Task<List<ResolvedInput>> GetUtxosAsync(List<string> address);
Task<ProtocolParams> GetParametersAsync();
Task<string> SubmitTransactionAsync(ITransaction tx);
Task<ResolvedInput?> GetUtxoByOutRefAsync(string txHash, ulong index);
Task<Metadata?> GetTransactionMetadataAsync(string txHash);
```

After:

```csharp
Task<List<ResolvedInput>> GetUtxosAsync(List<string> address, CancellationToken cancellationToken = default);
Task<ProtocolParams> GetParametersAsync(CancellationToken cancellationToken = default);
Task<string> SubmitTransactionAsync(ITransaction tx, CancellationToken cancellationToken = default);
Task<ResolvedInput?> GetUtxoByOutRefAsync(string txHash, ulong index, CancellationToken cancellationToken = default);
Task<Metadata?> GetTransactionMetadataAsync(string txHash, CancellationToken cancellationToken = default);
```

Validate arguments first, then check cancellation, then unsupported operations and
empty inputs. Forward the token to all requests and body reads. Do not turn a failed
read into an empty or partial result. See `ICardanoDataProvider` for the contract;
`ProviderHttp`, `ResolvedInputSet` and `ProviderValues` are reusable implementations.
Builders do not accept a token yet.

Search: `rg -n 'ICardanoDataProvider' --type cs`.

## Method groups

Change `addresses.Select(provider.GetUtxosAsync)` to
`addresses.Select(a => provider.GetUtxosAsync(a, cancellationToken))`, and
`Func<Task<ProtocolParams>> read = provider.GetParametersAsync` to
`Func<Task<ProtocolParams>> read = () => provider.GetParametersAsync(cancellationToken)`.
Blockfrost and Kupmios constructors also take an optional final `handler`;
you still own an injected handler.

Search: `rg -nP '\b(GetUtxosAsync|GetParametersAsync|SubmitTransactionAsync|GetUtxoByOutRefAsync|GetTransactionMetadataAsync|GetScript|EvaluateTransactionAsync|GetUtxosByPaymentKeys?Async|GetUtxosByOutRefsAsync|WaitForConfirmationAsync)\b(?!\s*[(<])' --type cs`.

## Errors instead of empty results

| Before | After |
|---|---|
| Blockfrost could return an empty or partial list, or `null`, on an HTTP failure | A failed read throws `ProviderStatusException` or `ProviderException`; only endpoint-specific absence returns empty or `null` |
| HTTP failures and parse errors could throw `InvalidOperationException`; an unknown cost-model key could throw `ArgumentException` | `ProviderException` |
| Unknown Kupo script language threw `NotSupportedException` | Non-transient `ProviderException` |
| Kupmios or Ouroboros metadata threw `NotImplementedException` | `NotSupportedException` |
| Kupmios `GetParametersAsync()` with `NetworkType.Unknown` threw `NotImplementedException` | `NotSupportedException` |
| Ouroboros could throw `IOException`, `SocketException` or `InvalidOperationException` | `ProviderException` |
| Kupmios could send malformed outref hashes; Ouroboros could throw `FormatException` for invalid Bech32; Blockfrost could send blank arguments | `ArgumentException` before I/O: Kupmios `GetUtxoByOutRefAsync` and `GetUtxosByOutRefsAsync` require 64 hex characters, Ouroboros `GetUtxosAsync` requires valid Bech32, and Blockfrost `GetUtxosAsync`, `GetScript`, `GetUtxoByOutRefAsync` and `GetTransactionMetadataAsync` reject blank strings. An empty Ouroboros address list does not connect. |
| A repeated asset unit or repeated/conflicting output could pass unnoticed | An error; identical outputs from different requests are kept once |
| A Kupo 404 meant no output | Status error; Kupo absence is a successful `[]` |
| Missing Kupo `coins` or `output_index` read as zero | Non-transient `ProviderException` through Kupmios; `JsonException` only when deserializing the DTO directly |
| Kupo could accept other omitted output/script fields | A match requires `transaction_id`, `output_index`, `address`, `value`, and `value.coins`. A `script` object, when present, requires both `language` and `script`. Missing fields are unusable responses through Kupmios and fail DTO deserialization. |
| A Kupo `inline` datum without datum bytes could be returned as a datum hash or no datum | Non-transient `ProviderException` |
| Kupmios returned only the first asset of a policy | Every asset |

Kupmios `GetUtxosByOutRefsAsync` now queries each hash/index pair once, including
hashes that differ only in letter case. A repeated requested pair yields at most one output.

Before, `if (utxos.Count == 0)` could treat a 403 or 429 as zero balance. Now
handle the failure separately:

```csharp
try
{
    utxos = await provider.GetUtxosAsync(addresses, cancellationToken);
}
catch (ProviderStatusException e) when (e.StatusCode == HttpStatusCode.Forbidden)
{
    // Check the configured project key or permissions.
    throw;
}
catch (ProviderException e) when (e.IsTransient)
{
    // A later read may succeed; use a bounded read retry policy.
    throw;
}
```

Log `Message` for the operation and fixed error facts. `Detail` is bounded server
text with known credentials masked; it is diagnostic only. Provider-thrown errors
no longer carry an inner exception. `UtxoRpcException` now derives from `ProviderException`.
Catch `UtxoRpcException` for gRPC status errors (`StatusCode`) and UTxO RPC-specific
unusable responses. Catch `ProviderException` to also handle duplicate or conflicting
outputs and non-gRPC transport failures, which throw the base type. Replace the
`UtxoRpcException(string, StatusCode, Exception)` constructor with
`UtxoRpcException(string, StatusCode, string detail)`; the standard constructors remain.

Search for catches near provider calls:
`rg -n 'catch\s*\((InvalidOperationException|NotImplementedException|NotSupportedException|ArgumentException|HttpRequestException|IOException|SocketException)' --type cs`.
Also search for `InnerException` on `UtxoRpcException` and for empty-result or null checks on the reads above.

## Retry reads, not submissions

Providers do not retry. Here is a handler that retries a GET once; see
`ProviderStatusException.RetryAfter` when scheduling a later read:

```csharp
sealed class RetryGetOnce(HttpMessageHandler inner) : DelegatingHandler(inner)
{
    protected override async Task<HttpResponseMessage> SendAsync(
        HttpRequestMessage request, CancellationToken cancellationToken)
    {
        if (request.Method == HttpMethod.Get)
        {
            try
            {
                var response = await base.SendAsync(request, cancellationToken);
                if ((int)response.StatusCode is not (408 or 429 or (>= 500 and <= 599)))
                    return response;
                response.Dispose();
            }
            catch (HttpRequestException) { }
            cancellationToken.ThrowIfCancellationRequested();
        }
        return await base.SendAsync(request, cancellationToken);
    }
}
```

Pass it as `new Blockfrost(projectId, NetworkType.Preprod, handler: retrying)`.
If a submission loses its answer, the transaction may have been accepted. A successful
HTTP status with a cut or unusable submit body also leaves the outcome unknown. Look
for the transaction by id, for example `GetUtxoByOutRefAsync(txId, 0, cancellationToken)`
or UTxO RPC's `WaitForConfirmationAsync`, before deciding what to do. Do not
replay a POST automatically or treat “unknown output reference” on a subsequent
attempt as proof the first submit failed.

## Bundle the two reads

```csharp
ProviderInputs inputs = await ((ICardanoDataProvider)provider)
    .GetInputsAsync(addresses, cancellationToken);
if (inputs.ParametersPoint is null || inputs.ParametersPoint != inputs.UtxosPoint)
{
    // Two reads that may come from different blocks.
}
```

The default implementation reads parameters and then UTxOs, once each. The
bundle does not imply that either answer has a known chain point or era. A tip
read before or after the operation does not make either read a snapshot.
