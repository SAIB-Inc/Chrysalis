# Migration — X12: Generated Typed Dispatch

## Summary

- Replaced reflection-based dispatch (`GetMethod`, `MakeGenericType`, `CreateDelegate`, `DynamicInvoke`) in `GenericSerializationUtil` with generated static registration in `CborCodecCache`.
- Removed `CborListReaderCache<T>` (and its mutable public static field `Reader`, eliminating the pre-existing `CA2211` suppression) in favor of the non-generic, thread-safe `CborCodecCache` API.
- Eliminated value-type boxing on primitive generic writes and removed all 9 Trim/AOT warnings (`IL2070`, `IL2090`, `IL3050`) from `Chrysalis.Codec`.

## Breaking Changes

1. **`CborListReaderCache<T>` removed:** Replace direct `CborListReaderCache<T>.Reader` reads or assignments with `CborCodecCache.GetReader<T>()` and `CborCodecCache.Register<T>` / `RegisterStruct<T>` / `RegisterReader<T>` / `RegisterStructReader<T>`.
2. **Manual non-`[CborSerializable]` types require explicit registration:** Concrete `[CborSerializable]` / `[PlutusData]` types (including Blueprint-generated types and Blueprint `ICborOption`/`CborList` shapes, official `[Union]` structs, built-in primitives, `Address`/`CborEncodedValue`/`CborAny`/`CborLabel`, and non-nullable open-generic structs such as `CborList<T>` and `CborMap<TKey, TValue>`) register automatically, as do closed open-generic types instantiated in compilations running `Chrysalis.Codec.CodeGen` (or already instantiated inside `Chrysalis.Codec`).
   - Hand-written types without `[CborSerializable]` passed through `CborSerializer`, `GenericSerializationUtil`, `CborList<T>`, or `CborMap<TKey, TValue>` must register once.
   - Consumers that do **not** run `Chrysalis.Codec.CodeGen` (or invoke closed generics dynamically without a closed generic syntax reference) and perform a cold `Deserialize<T>` on an open-generic class/interface (`ICborOption<T>`, `IReferenced<T>`, `Cip68<T>`), a cold `Deserialize<T?>` on a nullable open-generic struct not already instantiated in `Chrysalis.Codec` (e.g. `CborList<CustomType>?`), or a cold non-generic `GenericSerializationUtil.Read(data, typeof(ClosedOpenGeneric))` must either reference `Chrysalis.Codec.CodeGen` or register that closed type once via `CborCodecCache.Register<T>` / `RegisterStruct<T>` (or touch the non-nullable struct once).
   - `[Obsolete]`, `file`-local, `private`-nested, and `extern alias` concrete `[CborSerializable]`/`[PlutusData]` types — as well as same-assembly open-generic reference types parameterized by Blueprint-generated types on cold `Deserialize` — are excluded from auto-registration and must call `CborCodecCache.Register*` explicitly if dispatched via `CborSerializer`.
3. **Unregistered types fail fast with typed codec exceptions:** Unregistered reads throw `CborDecodeException` (`Expected = "registered CBOR type"`, `Actual = "unregistered type"`); unregistered writes throw `CborValidationException` with no reflection fallback or wrapped `NotSupportedException`.

## Before / After

```csharp
// Before:
CborListReaderCache<MyStruct>.Reader ??= MyStruct.Read;
var reader = CborListReaderCache<MyStruct>.Reader;

// After (value types — registers both T and T?):
CborCodecCache.RegisterStruct<MyStruct>(MyStruct.Read, MyStruct.Write);
var reader = CborCodecCache.GetReader<MyStruct>();

// After (reference types):
CborCodecCache.Register<MyClass>(MyClass.Read, MyClass.Write);
```
