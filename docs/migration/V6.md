# Value constants in Flat, a strict text parser, and valueData's size limit

This migration note targets the 2.0 release candidate.

`FlatDecoder.DecodeProgram` now reads `value` constants (Flat type tag 13). Before, any script holding one threw `InvalidOperationException`, so `Evaluator.EvaluateScript`, `ScriptApplicator.ApplyParameter`, `ScriptExtension.ApplyParameters` and `TransactionBuilder.Evaluate` failed on it. As on the node, a value is refused with `InvalidOperationException` unless it is canonical: currency symbols, and the token names under each, strictly ascending; no empty token list; no zero quantity; keys of at most 32 bytes; quantities from −2^127 to 2^127 − 1. Byte strings are now read in chunks of any size, and one whose padding ends inside a byte is refused, as the node refuses it. So is a `string` constant that is not valid UTF-8, and any `bls12_381_G1_element`, `bls12_381_G2_element` or `bls12_381_mlresult` constant; an empty list of those types still reads.

`FlatEncoder.EncodeProgram` now writes `value` constants and refuses one that is not canonical, so a `LedgerValue` built in code must already be in that form; `lookupCoin`, `insertCoin` and `valueContains` rely on it too, since they now search a value instead of reading all of it. It also refuses BLS12-381 constants, which no Flat reader accepts: pass the compressed bytes as a `bytestring` and uncompress them in the script.

`UplcParser.Parse` reads a value literal as written and throws `ParseException` unless it is canonical, as plutus's parser does. Before, it merged duplicate keys, sorted them and dropped zero quantities. It also throws `ParseException` for a comma just before the closing bracket of a list, array, value or data literal, which it used to skip.

```text
(con value [(#aa, [(#02, 3)]), (#aa, [(#01, 5)])])   refused: duplicate currency symbol
(con (list integer) [1, 2,])                         refused: comma before ]
(con value [(#aa, [(#01, 5), (#02, 3)])])            accepted
(con (list integer) [1, 2])                          accepted
```

The `valueData` builtin now fails, as a phase-2 error, for a value with more than 40,000 token entries, as the node's does.

`sliceByteString` now returns a view of its argument instead of a copy. If you evaluate a term whose byte string constant wraps an array you change later, copy the result first.
