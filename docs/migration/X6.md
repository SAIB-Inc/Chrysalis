# X6: Structured codec errors

`CborSerializer.Deserialize`, `Serialize`, `SerializeToMemory` and
`GetEncodedLength`, and run-time `GenericSerializationUtil.Read*` dispatch now
report codec failures as `CborDecodeException` or `CborValidationException`.
Both are `FormatException` subtypes; earlier facade calls used
`InvalidOperationException`, and `ReadAnyWithConsumed` with a run-time `Type`
could expose `TargetInvocationException`. Update catches for those old
wrappers. Cancellation and resource exhaustion still propagate.

Before:

```csharp
try
{
    var block = CborSerializer.Deserialize<BlockWithEra>(bytes);
}
catch (InvalidOperationException error)
{
    Report(error.Message);
}
```

After:

```csharp
try
{
    var block = CborSerializer.Deserialize<BlockWithEra>(bytes);
}
catch (CborDecodeException error)
{
    Report($"{error.TypePath} at byte {error.Offset}: expected {error.Expected}; found {error.Actual}");
}
```

`Offset` is zero-based in the input (`-1` for serialization failures without
a wire position). The original cause, when available, is in `InnerException`.
Lazy property getters may also throw a `FormatException` subtype, so existing
`catch (FormatException)` handlers may now catch malformed data in getters.
Direct calls to generated `Read` methods still may expose a raw SAIB.Cbor
`CborException`; use the serializer facade for consistent typed errors.

`UnknownEraException` still exposes the unsupported tag, preserved bytes and
envelope, but derives from `CborDecodeException`. For example, its message
changes from `Unsupported Block wire era tag 8.` to
`CBOR Block at byte 1: expected supported wire era tag; actual 8.`
Catch the type and inspect `WireTag` rather than matching message text. This
supersedes the generic-wrapper note in [C0a.md](C0a.md#unknown-era-tags).

The wallet CLI’s `verify` command still prints `Error: …` and exits with status 1 when a signature contains malformed COSE CBOR.
