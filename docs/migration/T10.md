# T10: Blockfrost provider

Normal `Blockfrost` callers keep the same methods, but receive ledger values instead of placeholders. If you construct or deserialize Blockfrost response DTOs or stub its HTTP calls, update those call sites too.

## Parameters

- Protocol version and governance values now come from Blockfrost. Absent values stay null, not zero or a placeholder. A composite (protocol version, execution units or prices, or voting thresholds) is null unless all its components are available.
- Ratios and prices are reduced and exact for the decimals Blockfrost publishes: `0.0577` now becomes `577/10000`, not `577000/10000000`. Blockfrost cannot recover an original non-terminating ledger ratio such as `2/3` from a published decimal.
- A Conway response (protocol major version 9 or higher, or an unknown version) with no reference-script fee price is unusable. A known pre-Conway response can omit the price.
- An absent `cost_models_raw` is unknown. Missing languages remain null; a null cost-model array for a named language is unusable.

## Outputs and scripts

- `GetUtxosAsync` keys outputs by `output_index`, never the deprecated `tx_index`. Outputs retain datum hashes when there is no inline datum.
- `GetUtxoByOutRefAsync` returns null for a spent output or an entry marked as collateral. An output without `consumed_by_tx` can still be returned: Blockfrost did not confirm whether it was spent.
- `GetScript` supports native scripts and rejects an answer whose script does not hash to the requested hash.
- Address paging is not a snapshot.

**Reference-script limit:** Blockfrost's address endpoint can return a null script hash even when the output carries a reference script. Treat null as unknown, not proof that the output has no script. Spending that output without the script reference populated on its resolved output omits its reference-script fee, and the node rejects the transaction with `FeeTooSmallUTxO`. Populate the resolved input's script reference (adding only a script witness does not restore the fee), or fetch the input by transaction hash and output index with `GetUtxoByOutRefAsync` (the transaction endpoint) so the reference script is known. The default address lookup makes no extra requests.

## Metadata

`GetTransactionMetadataAsync` now uses `txs/{hash}/metadata/cbor`. Update stubs for that route and supply a hexadecimal CBOR map with exactly one entry keyed by its label in each response item. Byte strings and integer keys retain their ledger types; Blockfrost returns re-encoded values, not the original transaction bytes.

## Response DTO changes

| Type | Changes |
| --- | --- |
| `BlockfrostProtocolParametersResponse` | Removed `Epoch`, `DecentralisationParam`, `ExtraEntropy`, `MinUtxo`, `Nonce`, and `CostModels`. Integer fields are `ulong?`; ratios, execution prices and `MinFeeRefScriptCostPerByte` are `decimal?`. `CostModelsRaw` is `Dictionary<string, long[]>?`. No fields are `required`. |
| `BlockfrostUtxo` | Removed `TxIndex`. `OutputIndex` is `ulong?`. Added `ConsumedByTx` (`string?`) and `Collateral` (`bool?`). |
| `Amount` | `Quantity` is `ulong?`. |
| `BlockfrostMetadataResponse` | The constructor is `(ulong? Label, string? Metadata)`; `Metadata` replaces `JsonMetadata`. |

The parameter DTO adds five `Pvt*` and ten `Dvt*` voting thresholds, as well as `CommitteeMinSize`, `CommitteeMaxTermLength`, `GovActionLifetime`, `GovActionDeposit`, `DRepDeposit`, and `DRepActivity`.

If you deserialize these DTOs directly, use `JsonSerializerOptions.Web`. The provider reads both JSON numbers and quoted numbers straight from the response bytes. That applies to UTxO amounts on both lookup paths, metadata labels, and parameter numbers including deposits, ex-unit limits, `max_val_size` and `coins_per_utxo_size`.

Find affected callers and stubs with:

```sh
rg -n 'BlockfrostProtocolParametersResponse|BlockfrostUtxo|BlockfrostMetadataResponse|TxIndex|JsonMetadata' --type cs
rg -n '/metadata"' --type cs
```

## Later

An opt-in per-transaction lookup could fill missing script hashes from the address endpoint. It would add up to one HTTP request per distinct transaction, so it is not on the default path.
