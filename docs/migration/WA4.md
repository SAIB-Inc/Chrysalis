# WA4: Public-key-only BIP32-Ed25519 soft derivation

`PublicKey` now supports watch-only BIP32-Ed25519 V2 soft child derivation backed by canonical Ed25519 point addition, plain non-extended 32-byte keys carry an empty chain code so they cannot silently derive unspendable addresses, and `Bip32Util.IsValidPath` enforces canonical BIP-32 path syntax.

- `PublicKey` adds soft-only BIP32-Ed25519 V2 derivation: `Derive(int)`, `Derive(RoleType)` (defined CIP-1852 roles only), `DerivePaymentKey(int = 0)`, and `DeriveStakeKey(int = 0)`. Hardened public derivation is unrepresentable at compile time; raw non-negative indices remain reachable via `Derive(int)`.
- `Chrysalis.Crypto.Ed25519` adds `PointAdd(byte[], byte[])` enforcing RFC 8032 §5.1.3 canonical decoding (`y < 2^255 - 19`, on-curve, `!(x == 0 && sign == 1)`) and canonical `X == 0` encoding (stricter than upstream `cardano-crypto`'s `ed25519_point_add`, which accepts non-canonical encodings and flips bit 255 unconditionally; honest Ed25519 keys are unaffected).
- Non-extended 32-byte keys now carry an empty `Chaincode` (`[]`) when returned by `PrivateKey.GetPublicKey()` on a 32-byte seed (previously forwarded whatever caller-supplied `Chaincode` was passed) or loaded by `KeyFileReader.ReadSigningKey` / `ReadVerificationKey` from a 32-byte CLI envelope (previously 32 zero bytes), so `PublicKey.Derive*` throws `InvalidOperationException` instead of deriving unspendable watch-only addresses. Because `PublicKey.Equals` and `GetHashCode` include `Chaincode`, comparing `new PrivateKey(seed, cc).GetPublicKey()` against a saved `new PublicKey(pk, cc)` changes from `true` to `false` when `cc` is non-empty (such as `new byte[32]`).
- `Bip32Util.IsValidPath` now enforces canonical BIP-32 paths starting with `"m/"` and one or more non-negative ASCII-digit indices (`0` to `2^31 - 1`, no leading zeros on multi-digit segments, at most one trailing `'`, no signs, whitespace, or trailing NULs): inputs such as `""`, `"m"`, `"x/1"`, `"m/ 1"`, `"m/+1"`, `"m/1852''"`, `"m/00"`, `"m/01'"`, and `"m/1\0/2"` now return `false` (previously `true`).
- `PrivateKey.Derive*` now throws `InvalidOperationException` when `Chaincode` is `null` or not 32 bytes (previously `ArgumentNullException` on `null`, or silent derivation on wrong length); the 32-byte seed check still runs first.
- `Bip32Util.PointOfTrunc28Mul8(byte[])` now throws `ArgumentException` with parameter name `"sk"` (previously `"y"`) when `sk` is not 32 bytes.
