# T14: UTxO RPC provider on the spec package

`UtxoRpc` now takes its UTxO RPC messages from the `Utxorpc.Spec` package instead of its own copy of the spec, and still speaks v1beta only.

## Packages

- `Chrysalis.Tx.Providers.UtxoRpc` now depends on `Utxorpc.Spec` 0.19.2-alpha, a prerelease package.
- An app that also references `Utxorpc.Spec` or `Utxorpc.Sdk` gets one `Utxorpc.Spec` version, the highest any of them asks for; keep it at 0.19.2-alpha or a later version that keeps v1beta compatible.
- The package no longer ships `licenses/utxorpc-spec/LICENSE`; the spec is Apache-2.0.

## Errors

- `GetUtxoByOutRefAsync`, `GetTransactionMetadataAsync` and `WaitForConfirmationAsync` report a bad hash with `ParamName` `txHash` (was `hash`): a null hash throws `ArgumentNullException` with the runtime's message, and a hash that is not 64 hexadecimal digits throws `ArgumentException` with the message "Expected a 32-byte transaction hash in hex." (was "Expected a 32-byte hash in hex.").
- `GetUtxosAsync` and `GetUtxoByOutRefAsync` throw `UtxoRpcException` "SearchUtxos: unusable response (…)" or "ReadUtxos: unusable response (…)" for an output with a malformed address, amount, datum hash or script reference. Before, they returned it, and the caller's first read of that field threw.
- New `ProviderValues.CheckedOutput(ITransactionOutput)` reads each field of a decoded output once, so a malformed field fails in the provider rather than in its caller; `UtxoRpc` and `Ouroboros` use it.

## Cancellation

- A cancel after the server has answered a single call no longer throws: `SubmitTransactionAsync` returns the accepted transaction's reference, as `Ouroboros` and the HTTP providers have since T12b; `GetParametersAsync`, `GetUtxoByOutRefAsync`, `GetTransactionMetadataAsync` and `GetUtxosAsync` for one address after its last page return what the server sent; and `WaitForConfirmationAsync` returns once its on-chain check has found the transaction.
- Reads that make several calls still throw `OperationCanceledException` before their next call, and `GetUtxosAsync` over several addresses and `GetInputsAsync` also after their last answer.

Find affected callers with:

```sh
rg -n 'ParamName|OperationCanceledException|Utxorpc' --type cs
```
