# Tier 2a-1a: Lazy `CborMap<TKey, TValue>` on map-backed Cardano models

`CborMap<TKey, TValue>` replaces eager `Dictionary<TKey, TValue>` on seven map-backed Cardano models (`MultiAssetOutput`, `MultiAssetMint`, `TokenBundleOutput`, `TokenBundleMint`, `RedeemerMap`, `AuxiliaryDataSet`, and `Withdrawals`), and `AuxiliaryDataSet` and `Withdrawals` become `readonly partial record struct` value types.

- **Property type change:** `.Value` on all seven models is now `CborMap<TKey, TValue>` instead of `Dictionary<TKey, TValue>`. Direct `foreach (var (k, v) in model.Value)` and `foreach (KeyValuePair<K, V> kv in model.Value)` enumerate deduplicated ledger entries via a `ref struct` enumerator (`CborMapEnumerator<TKey, TValue>`). Unique maps retain no lookup table: on eligible definite value-type/byte-slice maps, `Read` uses stack storage up to 32 distinct keys and targets 0 B above 32 with a warmed, available `ArrayPool<int>.Shared` bucket, while direct `foreach` and `TryGetValue` allocate 0 B. Exceptions that allocate: pool cold-rent/miss/trim above 32 distinct keys, maps with duplicate wire keys (one `int[2 * distinctCount]` index on `Read`, 0 B on subsequent eligible direct `foreach`), reference keys (`RewardAccount`), interface union values (`IAuxiliaryData`), indefinite `0x5F` byte strings, and boxed `IEnumerable`/LINQ paths.
- **X7 duplicate-key semantics preserved:** Following `docs/migration/X7.md`, `Count`, `foreach`, boxed enumeration, `TryGetValue`, `ContainsKey`, `this[key]`, and `ToDictionary()` retain each duplicate key's **first-seen key and insertion position** paired with its **last-seen value** under semantic key equality (`ReadOnlyMemoryComparer` / `LedgerKeyComparers`), while `Raw` preserves exact original wire bytes verbatim. Compatibility with .NET `Dictionary` refers to lookup and deduplication semantics, not exact exception messages.
- **Lookups and materialization:** `TryGetValue`, `ContainsKey`, and `this[key]` perform a linear O(N) scan with semantic key equality (stopping on the first match); call `.ToDictionary()` once before probing the same map repeatedly in a loop. `.Keys` and `.Values` properties are not exposed on `CborMap<TKey, TValue>` (use `foreach ((var k, _) in map)` or LINQ `.Select(kv => kv.Key)`).
- **Construction & `[]`:** Wrap entries with `CborMap<TKey, TValue>.Create(entries, isIndefinite: false)` before calling `MultiAssetOutput.Create(...)`, `TokenBundleOutput.Create(...)`, `MultiAssetMint.Create(...)`, `TokenBundleMint.Create(...)`, `RedeemerMap.Create(...)`, `AuxiliaryDataSet.Create(...)`, or `Withdrawals.Create(...)`. Empty collection expressions `[]` (e.g. `RedeemerMap.Create([])`) build a valid empty `0xA0` map via `[CollectionBuilder]`, whereas `default(CborMap<TKey, TValue>)` throws `CborValidationException` on write. CLR `null` keys throw `ArgumentNullException` on `Create`; CLR `null` values and `ICborType` items backed by CBOR wire null (`0xF6`) throw `CborValidationException` on `Create`/`Write`; wire `0xF6` keys and values throw `CborDecodeException` on access; and custom non-`ICborType` writers used in fresh maps must not emit CBOR wire null (`0xF6`) (absent/null `CborMap<K, V>?` properties remain supported).
- **Deferred value validation:** Lazy `Read` (including `Deserialize`) checks wire structure and decodes keys, but does not decode values. A structurally valid map with a malformed typed value throws when that value is decoded by `foreach`, `TryGetValue`, or `ToDictionary()`, not on `Deserialize`.
- **Struct conversion for `AuxiliaryDataSet` and `Withdrawals`:** Replace `new AuxiliaryDataSet(dict)` with `AuxiliaryDataSet.Create(CborMap<int, IAuxiliaryData>.Create(dict))`, and `new Withdrawals(dict)` with `Withdrawals.Create(CborMap<RewardAccount, ulong>.Create(dict))`. Both types remove positional `Deconstruct`, `with { Value = ... }`, and settable `Raw`, `ConstrIndex`, and `IsIndefinite`. Read `.Value` directly; to edit, copy with `.Value.ToDictionary()`, modify the copy, and rebuild. `Withdrawals?` is now `Nullable<Withdrawals>`; unwrap with `if (body.Withdrawals is { } withdrawals)`. Generic `CborSerializer.Deserialize<Withdrawals?>` and `Deserialize<AuxiliaryDataSet?>` continue to work on valid CBOR bytes.
- **`TransactionBuilder` withdrawals:** `AddWithdrawal` deduplicates by `CborMap<RewardAccount, ulong>.KeyComparer` (last amount wins). `IntegrateWithdrawals` merges entries and builds a new immutable `Withdrawals`, so adding to a decoded `Withdrawals` no longer silently drops the additions.
- **`CborEncodedValue` generic serialization fix:** Fresh `CborEncodedValue` instances serialized through `CborSerializer.Serialize` / `GetEncodedLength` / `CborMap` / `CborList` now write `#6.24(bstr)` (`D8 18 ...`) when `Raw` is empty (preserving `Raw` verbatim when non-empty), matching enclosing generated fields instead of dumping unframed inner bytes.
- **Decode error paths:** Decode failures inside the seven migrated maps now report `.CborMap.entry` in `CborDecodeException.TypePath` (previously `.entry` for the five former `Dictionary`-property models), with exact rebased byte offsets.
- **Borrowed slices & equality:** Definite `ReadOnlyMemory<byte>` keys/values decoded from a `CborMap` borrow the input buffer; keep it valid and unmodified, and call `.ToArray()` to retain slices independently (indefinite `0x5F` byte strings remain owned copies). Equality on `CborMap<TKey, TValue>` compares backing storage (`Raw` / entry array), not map contents. Built-in `byte[]` keys compare by byte content and hash the full span; custom lazy keys must compare equal after re-decoding, so reference-identity equality will not work.
- **Convenience extensions kept:** `BlockExtensions.AuxiliaryDataSet()`, `TransactionBodyExtensions.Withdrawals()`, and `RedeemerExtensions.ToDict()` continue returning `Dictionary<,>` via `.ToDictionary()`. `ValueExtensions.ToAssetList()` retains deferred streaming over boxed `IEnumerable`.
