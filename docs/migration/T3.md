# Exact fees in transaction builders

`TxBuilder.Complete`, `TransactionTemplateBuilder`, and `TransactionBuilder.CalculateFee` now price their own bytes with `Chrysalis.Tx.Fees.FeeEngine`.
They use the least valid fee for the estimated signing set, honoring a minimum fee and padding when configured.
The signing estimate counts the ledger's spending and collateral keys, withdrawals, certificates, required signers and voters, and the keys named by needed native scripts. It also accounts for Byron bootstrap witnesses. A change recipient does not add a signature. For native `any` and `at least` scripts, the estimate includes all their keys.

Sign only after pricing: a VKey or bootstrap witness already on the builder is rejected. If you will add signatures beyond the estimated set, use a fee floor or increase the low-level `mockWitnessFee` VKey count.
Pricing throws `NotSupportedException` for legacy `GenesisKeyDelegation` and MIR (`MoveInstantaneousRewardsCert`) certificates.

Script evaluation is strict: `Evaluate`, `TxBuilder.Complete`, and `TransactionTemplateBuilder` throw when evaluated `(tag, index)` results are missing, duplicate, or unknown rather than keeping placeholder execution units. `ComputeScriptExecutionFee` (and `FeeEngine.ScriptFee`) rounds the summed memory and step costs up once instead of rounding per redeemer or truncating, so script execution fees can be higher than in 1.x.

When no more inputs can be added, ADA-only change below its minimum can go into a free fee. Token-bearing change is never dropped. Payments above their minimum stay at the requested amount.

Low-level `CalculateFee`:

- `CalculateFee` gained the optional `referenceInputs` parameter (source-compatible, binary-breaking; recompile callers built against 1.x). Pass `referenceInputs:` with the resolved read-only UTxOs. With any resolutions supplied, every spending, collateral and reference input must resolve. Reference inputs never fund change.
- If no resolutions are supplied, the builder assumes no input carries a reference script and estimates `mockWitnessFee` VKey witnesses. With resolutions, `mockWitnessFee` is a floor. `scripts` supplies the language for the script-data hash, not the billed reference-script size.
- A nonzero `defaultFee` is fixed. If it doesn't cover the fee required by its own bytes or would leave invalid change, calculation throws instead of changing it.
- `Sign` preserves the scripts, data, redeemers and bootstrap witnesses of an Alonzo witness set.

## Replace `FeeUtil`

| Old method | Use instead |
|---|---|
| `CalculateFee` | `FeeEngine.LinearFee(ledgerSize, parameters)` |
| `CalculateFeeWithWitness` | `FeeEngine.MinFee(transaction, parameters, extraVKeyWitnesses)` |
| `CalculateReferenceScriptFee` | `FeeEngine.ReferenceScriptSize` on resolved inputs, then `FeeEngine.ReferenceScriptFee(size, parameters)` |
| `CalculateScriptExecutionFee` | `FeeEngine.ScriptFee(redeemers, parameters)` |
| `CalculateMinimumLovelace` | `FeeEngine.MinLovelace(output, coinsPerUtxoByte)` for the given bytes, or `FeeEngine.LeastValidCoin(output, coinsPerUtxoByte)` to set its coin |
| `CalculateRequiredCollateral` | `FeeEngine.RequiredCollateral(fee, collateralPercentage)` |

Conway and later require a reference-script price when a nonzero reference-script size is billed. An explicit pre-Conway protocol version pays no reference-script surcharge.
