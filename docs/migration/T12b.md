# T12b: Ouroboros connection reuse and reply time limit

`Ouroboros` now reuses one idle node connection across sequential calls instead of opening a socket per call, implements `IDisposable` and `IAsyncDisposable`, is `sealed`, and exposes `ReplyTimeLimit`.

## Lifecycle and disposal (breaking)

- `Ouroboros` is now `sealed` and implements `IDisposable` and `IAsyncDisposable`. Dispose every instance you construct with `await using` (preferred in async code; waits for the read loop and socket to close) or `using`. Failing to dispose leaves the idle Unix socket and multiplexer loop open and triggers CA2000 under analyzers.
- Sequential calls reuse one healthy connection; overlapping calls open their own connections and keep at most one idle connection afterwards. A failed or cancelled call closes its connection. An idle connection already observed closed by the node between calls is replaced silently on the next call; if the node closes it just as a call starts (before EOF is read), that call fails as a transient error and is not retried.
- Calling `GetParametersAsync`, `GetUtxosAsync`, `GetUtxoByOutRefAsync`, or `SubmitTransactionAsync` after disposal throws `ObjectDisposedException`. Disposing the provider while a call is in flight interrupts it with `ObjectDisposedException`; a submission interrupted this way may still have been accepted, so check by transaction id.
- `AddCardanoProvider` registers `Ouroboros` as a singleton behind `ICardanoDataProvider`; the DI container disposes it automatically when the `ServiceProvider` / host shuts down (`Dispose` or `DisposeAsync`).

## Reply time limit for slow mainnet queries

- `Ouroboros.ReplyTimeLimit` defaults to 180 seconds (matching `NodeClient.ReplyTimeLimit`) and applies to every connection the provider opens or reuses. The handshake keeps its fixed 10-second limit.
- A large by-address UTxO query on mainnet (`GetUtxosAsync`, where the node scans the whole UTxO set) can run longer than 180 seconds. Raise `ReplyTimeLimit` or set it to `Timeout.InfiniteTimeSpan` to turn the limit off (zero, other negative values, and values longer than `uint.MaxValue - 1` ms throw `ArgumentOutOfRangeException`):

```csharp
await using Ouroboros provider = new(socketPath, Ouroboros.GetNetworkMagic(NetworkType.Mainnet))
{
    ReplyTimeLimit = TimeSpan.FromMinutes(10),
};
// Or turn the limit off:
provider.ReplyTimeLimit = Timeout.InfiniteTimeSpan;
```

With `AddCardanoProvider` (DI), resolve the singleton before the first query (resolving opens no socket) and set `ReplyTimeLimit` on it; disposing the `ServiceProvider` disposes the `Ouroboros` singleton. `BuildServiceProvider` needs the `Microsoft.Extensions.DependencyInjection` package; an ASP.NET Core or Generic Host app already has it and can resolve `ICardanoDataProvider` from its own services instead:

```csharp
using Chrysalis.Tx.Extensions;
using Chrysalis.Tx.Models;
using Chrysalis.Tx.Providers;
using Microsoft.Extensions.Configuration;
using Microsoft.Extensions.DependencyInjection;

IConfiguration configuration = new ConfigurationBuilder()
    .AddInMemoryCollection(new Dictionary<string, string?>
    {
        ["Provider"] = "Ouroboros",
        ["NetworkType"] = "Mainnet",
        ["OuroborosSocketPath"] = socketPath,
    })
    .Build();

ServiceCollection services = new();
services.AddCardanoProvider(configuration);

await using ServiceProvider serviceProvider = services.BuildServiceProvider();
Ouroboros ouroboros = (Ouroboros)serviceProvider.GetRequiredService<ICardanoDataProvider>();
ouroboros.ReplyTimeLimit = Timeout.InfiniteTimeSpan;
```

## Clean peer closes and late cancellation

- A clean socket close by the node (`ConnectionClosedException` with no inner exception) is now reported as a transient `ProviderException` with empty `Detail` (and still ends `; the transaction may have been accepted` on `SubmitTransactionAsync`).
- If a caller cancels after `Ouroboros` has received `AcceptTx` (or after an HTTP provider's `ProviderHttp.ReadJsonAsync` has finished reading the JSON response body), `SubmitTransactionAsync` now returns the transaction id instead of throwing `OperationCanceledException`.
- The same holds for reads: an `Ouroboros` read whose state-query release has gone out, and an HTTP provider's read whose JSON body has been read, return their result instead of throwing `OperationCanceledException`.

Find affected callers with:

```sh
rg -n 'new\s+Ouroboros\(|Ouroboros\s+\w+\s*=\s*new\(|:\s*Ouroboros\b' --type cs
```
