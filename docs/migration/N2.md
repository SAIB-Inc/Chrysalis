# Local transaction submission rejection

## A refused transaction returns its rejection

`LocalTxSubmit.SubmitTxAsync` now returns the node's `RejectTx` when the node
refuses a transaction. Before, every real rejection threw `CborDecodeException`
and left the reply unread, so the next call on that connection failed too. Check
the returned message's type (`AcceptTx` or `RejectTx`) instead of catching the
exception.

`RejectTx.RejectReason`, in `Chrysalis.Network.Cbor.LocalTxSubmit`, changes type
from `CborEncodedValue` to `CborAny`, and so does the parameter of
`LocalTxSubmissionMessages.RejectTx`. The node sends its reason inline
(`[2, reason]`); the old type expected a tag-24 byte string. Rebuild code that
names the property, the record's constructor or its deconstructor; code that
builds a rejection passes `new CborAny(reasonBytes)`.

Before:

```csharp
ReadOnlyMemory<byte> reason = rejection.RejectReason.Value;
```

After:

```csharp
if (await submit.SubmitTxAsync(message, token) is RejectTx rejection)
{
    ReadOnlyMemory<byte> reason = rejection.RejectReason.Raw;
    string text = rejection.Describe();
}
```

`Raw` is the reason exactly as the node sent it: `[[era, errors]]` when the
ledger rejected the transaction, or `[transactionEra, ledgerEra]` when the
transaction is for another era than the node's ledger, each era `[index, name]`.

## Reading the reason

`RejectTx.Describe()` gives the reason as text, for example:

- `Rejected in era 6: [[7, "All inputs are spent. Transaction has probably already been included"]]`:
  the era index, then the era's errors in CBOR diagnostic notation (RFC 8949 §8),
  with text strings JSON-escaped through `JsonEncodedText` using
  `JavaScriptEncoder.UnsafeRelaxedJsonEscaping` (escaping `"`, `\`, control
  characters, and any other code points that encoder forbids);
- `Era mismatch: the transaction is for Shelley (1), but the node's ledger is in Byron (0).`

Any other reason is shown whole in diagnostic notation. `Describe` never throws:
a reason it cannot show is given whole as hex, `h'…'`. That is a reason holding
a float, a simple value other than `false`, `true`, `null` and `undefined`, a
negative integer below -2^63 or an indefinite-length text string, one nested
more than 64 levels deep, or one that is not well-formed.

The node provider `Ouroboros` now reports a rejected `SubmitTransactionAsync` as a
`ProviderException` saying "transaction rejected", where before it named a
decoding exception.
