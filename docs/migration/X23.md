# Packages

## Protocol parameters

`ProtocolParams` now belongs to `Chrysalis.Codec`, in the namespace
`Chrysalis.Codec.Types.Cardano.Core.Protocol`. Replace
`using Chrysalis.Network.Cbor.LocalStateQuery;` with
`using Chrysalis.Codec.Types.Cardano.Core.Protocol;` in files that use only
`ProtocolParams`. Keep both imports when a file also uses query responses such as
`CurrentProtocolParamsResponse`, which remain in `Chrysalis.Network`.

The fields, constructors and CBOR representation of `ProtocolParams` are unchanged.
Search for `ProtocolParams` to find affected call sites.

## Providers

| Type | Package to reference |
|---|---|
| `Blockfrost` | `Chrysalis.Tx.Providers.Blockfrost` |
| `Kupmios` | `Chrysalis.Tx.Providers.Kupmios` |
| `Ouroboros` | `Chrysalis.Tx.Providers.Ouroboros` |

The provider types keep the `Chrysalis.Tx.Providers` namespace and their existing
constructors and methods. Add the matching package reference when installing
`Chrysalis.Tx` directly. Only the Ouroboros provider needs `Chrysalis.Network`;
transaction builders and the other two providers no longer bring it in.
The UTxO RPC provider (`Chrysalis.Tx.Providers.UtxoRpc`) also no longer brings
`Chrysalis.Network`. Add an explicit Network package reference if your application
also uses its node client or query types.

The `Chrysalis` umbrella brings the six libraries and all three providers as
package dependencies, rather than embedding their assemblies. Consumers that
already reference `Chrysalis` need no additional provider references. The UTxO RPC
and Koios providers are not included in the umbrella.

## Provider registration

`ServiceCollectionExtensions.AddCardanoProvider` now belongs to the `Chrysalis`
umbrella package, not `Chrysalis.Tx`. Add a reference to `Chrysalis` if you use this
configuration-based dispatcher. Its `Chrysalis.Tx.Extensions` namespace,
configuration keys and behaviour are unchanged. Consumers that want only one
provider can reference its package and construct it directly, as before.

`Chrysalis.Tx` no longer brings `Microsoft.Extensions.Configuration.Binder`. Add
that package directly if your application uses binding helpers such as
`IConfiguration.GetValue<T>`.

## Rebuilding libraries

Rebuild third-party libraries compiled against the alpha that use the moved
types: the providers change assembly, and `ProtocolParams` changes both assembly
and namespace. Type forwarding cannot preserve these old type identities:
forwarding providers from Tx would create a dependency cycle, and forwarding
cannot change `ProtocolParams`' namespace.
