# Migration to 2.0.0-alpha

This is an unpublished candidate. Public changes are made for protocol correctness, not tidiness. Source and binary compatibility breaks require rebuilding callers. The capability claims and provisional N2C default are recorded in `MANIFEST.md`.

## Five approved node-to-client type-change groups

The first four groups are approved by D5 and belong to B2–B4; listing them here does not claim those repairs have landed in this B1 change.

1. **LocalTxMonitor.ReleaseAsync**: the repaired API returns `Task`, not a task containing a protocol reply: Release has no server response. Await completion of the send, then reacquire if needed (B4).
2. **Mempool measures**: the measures element type changes from 32-bit to 64-bit to represent actual node capacities without overflow. Update collection element types and avoid narrowing conversions (B4).
3. **Result.QueryResult**: the result becomes an inline raw CBOR value instead of the incorrect outer representation. Decode the query-specific ledger payload from the inline value (B2).
4. **RejectTx.RejectReason**: the reason becomes inline raw CBOR instead of the incorrect byte-string representation. Decode the structured node rejection without assuming that the node supplied a CBOR byte string (B3).
5. **HandshakeDecodeError.ErrorData and Refused.ErrorData**: both members change from `ReadOnlyMemory<byte>` to **`string`** (D26, B1). The node sends CBOR text, so read `ErrorData` directly; explicitly UTF-8 encode only when bytes are required by a caller. The member names are retained. There is no `ErrorText` accessor, converter bridge or generator change. A fresh record writes CBOR text, and CBOR byte-string/null payloads are rejected. This fifth group has its own described commit boundary because retaining the byte declaration could never decode a node's actual text and would require unnecessary generator support.

## Other B1 public deltas (one described commit boundary each)

| Public delta | Migration and reason |
|---|---|
| N2C wire-family validation | Serialized/deserialized `N2CVersion.Value` must be a Word16 with bit 15 set (32768–65535). Values are **wire** numbers, not logical version numbers: V23 is 32791. Wrong-family/out-of-range values are rejected by the declarative codec; constructors remain unchanged. Future values within the family remain representable for explicit, untested offers. This disambiguates N2C from N2N accept/query-reply shapes. |
| N2N wire-family validation | Serialized/deserialized `N2NVersion.Value` must be 0–32767. Use the correct version type; constructors remain unchanged. This prevents the N2N union alternative from consuming an N2C reply. The default N2N offer still ends at V14. |
| Typed `HandshakeRefusedException` | `Handshake.SendAsync<T>` first reads the reply union and throws this exception for a node refusal. Catch it and inspect `Reason` (`VersionMismatch`, `HandshakeDecodeError` or `Refused`); string payloads remain intact. Malformed local CBOR is not a typed node refusal. Unexpected non-refusal reply types produce `InvalidOperationException`. For an empty query-reply table, the generic overload uses the **proposal's family** (N2C or N2N), not the requested return type; nonempty tables retain wire-key family validation. Non-generic `SendAsync` still returns the raw context-free union: an empty map is **family-ambiguous** without interpreting the proposal, so its union alternative does not establish the peer's family. The same generic repair benefits PeerClient without expanding its N2N default. |
| `NodeClient.NegotiatedVersion` | Read the nullable accepted version instead of assuming the maximum offered version was selected. It is null before successful startup and on startup failure. The accepted offer/network data are checked before publication. |
| Explicit-offer/cancellable `NodeClient.StartAsync(N2CVersionTable, CancellationToken)` | A one-entry table forces a version; all entries must share a network magic and query=false. An explicit untested in-family version does not change default support. Cancellation applies to startup, not the accepted connection's lifetime. Startup can run only once per connection. The original `StartAsync(ulong networkMagic = 2)`, including `StartAsync()` binding and magic 2 default, is unchanged. Use raw handshakes for query mode. |
| V21–V23 constants and extended default table | `N2CVersions` adds V21/V22/V23. The historical `VersionTables.N2cV10AndAbove` name is retained for compatibility; its provisional default offer is V16–V23, subject to the documented B1 controls and the mandatory full-suite rerun after B2–B4 before H2. A failing version leaves the default at that gate. |
| `N2CVersionNotSupportedException` and explicit-version standalone constructors | NodeClient supplies negotiated context to LSQ/monitor handlers. Insufficient-version requests throw **before any write**, with operation, required and negotiated version metadata. Built-in Conway raw queries require V16; GetMeasures requires V20. Direct users can pass their negotiated version to the new handler constructors. Existing single-channel constructors retain legacy built-in/GetMeasures behavior with no context; no negotiation is invented. SDK-owned context before handshake success rejects version-dependent calls with `InvalidOperationException`. |
| Synchronous `LocalStateQuery.QueryAsync(query, minimumVersion, cancellationToken)` overload | Custom raw queries with higher requirements must supply their true minimum. The overload validates synchronously before returning the existing send/receive task; it adds no async stage, channel or hand-off. Without negotiated context this explicit-check overload throws `InvalidOperationException`, rather than pretending that an unchecked send was checked. |

The two text members form the single fifth type-change group and a single D26 boundary. The other boundaries above match the individually described public deltas; implementation/test/provenance and documentation changes do not authorize unrelated API changes.

N2CVersion and N2NVersion now compare and hash by numeric Value only, ignoring Raw and decoder metadata. A decoded version equals its well-known constant and can look up a version-table dictionary key; callers needing encoding identity must compare Raw explicitly. CborRecord equality for all other types is unchanged.
