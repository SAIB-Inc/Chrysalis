# Integration tests

These xUnit 2.9.3 / net11.0 tests use environment-only configuration. They currently reference the source projects; this is not the later installed-package integration gate. Every case has `Category=Integration`, including offline model and harness-contract cases. Discovery marks a missing required variable as **Skipped**, naming the missing variables. No credential file is read during discovery. A non-loopback N2N host produces an explanatory discovery skip and is also refused at connection time. Other invalid endpoint/network values fail rather than skip; an absent or disabled funded opt-in is intentionally a skip.

## Lanes

From the repository root, `scripts/integration/run.sh` runs:

`Category=Integration&Known!=B2&Known!=B3&Known!=B4&Known!=F2`

The default filter excludes only these Known traits, not methods or classes. `scripts/integration/run.sh --include-known` selects exactly `Category=Integration`, including correct expectations that currently expose production defects. Phase 1 removes the corresponding Known traits when repairing those defects. `scripts/integration/run.sh --funded` selects just the explicitly configured funded route and sets `CHRYSALIS_IT_FUNDED=1` for that invocation only. Routine and `--include-known` runs explicitly clear any inherited funded opt-in, even if a wallet path was left in the environment. Extra arguments (for example `--no-build --logger trx --results-directory ...`) are forwarded to `dotnet test`. The wrapper uses `heavy` when it is on PATH, otherwise it runs `dotnet` directly; both paths retain `-m:8`. In this controlled workspace `heavy` is mandatory and present: an exit of 75 means wait and retry, not bypass the resource gate. A preconfigured `NUGET_PACKAGES` value is preserved exactly; only an unset value defaults to `$HOME/.nuget/packages`. No parent-worktree directory layout is assumed.

| Trait | Correct expectation, currently broken |
| --- | --- |
| B2 | Five LSQ helpers and Ouroboros parameters unwrap the same-node ledger result and agree with CLI |
| B3 | LocalTxSubmit rejection is inspectable, not a CBOR decoder exception |
| B4 | Tx monitor release has no response; has-tx uses a byte-string id; measures have the actual count/byte semantics |
| F2 | Blockfrost Preprod parameters equal CLI, including protocol version and governance values, not placeholders |

`dotnet test -m:8 --filter 'Category!=Integration'` (through `heavy`, with the required local NuGet environment) preserves the existing unit cases and excludes this entire assembly's cases. A wallet path alone never authorizes spending. Use a separate exact `--funded` lane; direct `dotnet test` requires both the wallet path and explicit `CHRYSALIS_IT_FUNDED=1` for that invocation. Other opt-in values produce a real disabled-funding skip.

## Configuration

All node tests require:

- `CHRYSALIS_NODE_SOCKET`: Unix socket of the node used by both SDK and CLI.
- `CHRYSALIS_NETWORK_MAGIC`: unsigned testnet magic (Preprod is `1`).
- `CHRYSALIS_NODE_VERSION`: actual running node tag, recorded as provenance.
- `CHRYSALIS_CARDANO_CLI`: executable path or name. The independently verified producer is CLI 10.13.1.0; an unreviewed version fails the identity assertion until `Golden/SOURCES.json` is reviewed and updated.
- `CHRYSALIS_INTEGRATION_OUTPUT`: directory for public CLI output, provenance and funded receipts; keep outside the tracked tree or use ignored `.integration-artifacts/`.

Additional route configuration:

- UTxO helper: `CHRYSALIS_QUERY_ADDRESS`, a **public Preprod reference address currently holding at least one UTxO**. Obtain it from public wallet-address evidence, never a key file. The missing-variable skip explains this requirement. An empty CLI result fails the oracle precondition before the SDK query. Inputs, full addresses, lovelace, every native asset, datum hash/inline datum CBOR and reference script are compared; matching empty maps cannot pass. The by-input route selects an actual txid#index from that CLI address result, then asks both CLI and SDK for that same single input and requires a nonempty full-output match. Only the offline captured empty response (`c1-in-p7-011.cbor`) is asserted empty.
- N2N: `CHRYSALIS_N2N_HOST`, `CHRYSALIS_N2N_PORT`. The peer must be the **same node** as the CLI socket, not an unrelated public relay. Only numeric loopback addresses or `localhost` are accepted; remote hosts cause a clear discovery skip and are refused again before connecting. `localhost` is normalized to numeric loopback, without DNS. The operator must still connect that loopback port/proxy to the same node; loopback alone cannot prove the forwarding target. If Docker's bridge is inaccessible, the optional `scripts/integration/node-proxy.py --container NAME --listen-port PORT` exposes only loopback and does not start the container. SIGINT, SIGTERM and SIGHUP use the same orderly stop/CHECK path, close every active relay and join its children. Startup reports a private nonce-bound PID/start identity on stderr and requires a host acknowledgement before forwarding payload. Normally stdin EOF lets the container shell reap both cats. If a cat is blocked writing and cannot observe EOF, bounded out-of-band Docker exec cleanup validates that exact relay identity, signals only its supervisor/owned cats and checks that it is gone before treating shutdown as successful; cleanup is scoped to the validated relay and its owned children and does not stop the container. Start/nonce and unreaped-child ownership/start checks are refreshed immediately before signals. The tiny numeric-PID counter-wrap window between adjacent builtins is explicitly accepted for this optional test helper instead of adding pidfd dependencies. After an accepted exact-target signal it discards at most 256 KiB of abandoned queued stdout and closes that host pipe, so Docker attach cannot deadlock while flushing to a non-reading client. Every identified exit path, including host exit 0, requires an independent container-PID check. A remaining live relay is cleaned and checked again, or shutdown is marked failed; host CLI exit alone never proves cleanup. Cleanup return codes, bounded stdout/stderr, elapsed times and precise identity-refusal reasons are retained; peer payload bytes are never logged. It uses only the local Unix Docker endpoint and an OS-only environment allowlist; credential-file and remote-context variables are not inherited.
- Blockfrost: `CHRYSALIS_BLOCKFROST_KEY_FILE` is an operator-supplied absolute path to the protected original credential file (there is no built-in location); magic must be `1`. Only this test process reads it, for one parameter request. No raw HTTP is recorded. Header stripping and secret redaction are applied to the recreated exception; the original exception is never retained as an inner exception.
- Funded: `CHRYSALIS_IT_FUNDED=1` **for this invocation**, `CHRYSALIS_WALLET_KEY_FILE`, and public `CHRYSALIS_IT_COLLATERAL_TXIN=txid#index` are all required. Missing collateral configuration is a real skip. That exact outref must exist in the wallet address's **unfiltered** CLI UTxO map and is excluded at every value; collateral carrying tokens is still recognized, and no collateral amount is assumed. With an explicitly configured public wallet address, this check runs before reservation/key access; otherwise the address must first be derived from the key, and a fresh unfiltered snapshot is checked before any input selection. `CHRYSALIS_WALLET_KEY_FILE` points at the original protected payment key. Only this C# test reads it. Optional `CHRYSALIS_WALLET_ADDRESS` selects the public wallet address (otherwise derive an enterprise address). The payment credential and testnet network id are verified before use. Magic must be `1`.

Never place a key value in a command, environment variable, log or artifact. Never copy the wallet file, echo a credential file, enable `set -x`, or pass credential-file configuration to CLI children. `OracleCli` clears the child environment except a minimal OS allowlist. Wallet secret errors are replaced with a non-sensitive stage failure; private key arrays are cleared. The original wallet file is never modified.

## Independent expectations and provenance

The oracle is the real `cardano-cli` executable on the same node, not SDK roundtrips. CLI source tag/commit/path/license are in `Golden/SOURCES.json`; its Apache-2.0 license is retained. The installed binary reports zero git revision, so the official source tag is identified separately from the recorded executable SHA-256; this is not a reproducible-binary assertion. `golden-oracles.jsonl` records each generated output's SHA-256, CLI arguments, source identity, binary identity, node tag and network magic. Current chain state and a newly constructed transaction cannot be pre-existing upstream vectors. SDK observations are kept separate and are not called CLI goldens.

Offline fixtures are reused unchanged from `Chrysalis.Network.Tests/Fixtures/Preprod`. Their existing manifest records per-file hashes and capture provenance/limitations. The complete address/value/absent-datum/absent-script expectation for `c1-in-p7-009.cbor` is also recorded independently in `Golden/utxo-by-address-expected.json`, decoded with cbor2 5.8.0 (MIT); `Golden/SOURCES.json` records its capture and expectation hashes. Those model tests deliberately extract the ledger payload: they do not silently bless the known-broken outer LSQ wrapper. CLI comparisons retry boundedly when the tip changes; no assumption is made that a public chain is static. Measures requires two equivalent independent CLI size/count snapshots before calling Chrysalis, then another equivalent snapshot afterward. Movement retries at most three times, each with a fresh SDK connection. Public precondition artifacts identify the oracle-ready stage separately from Known B2/B4 decoder failures.

The funded build uses a test-only CLI snapshot adapter because the native LSQ production provider is currently defective. It builds and signs with the production builder/wallet, verifies transaction id and minimum fee with CLI, submits with production LocalTxSubmit, and observes confirmation with CLI. It is a single 2 ADA self-transfer, all outputs return to the wallet, and only the fee is spent. The fee cap is 500,000 lovelace. An ADA-only input of at least 5 ADA is required. The configured collateral **outref**, not any assumed amount, is excluded from selection. Only the selected spending input is given to the test-only snapshot provider. The signed body must contain exactly the selected input (no extra or duplicated input), asserted again immediately before submission.

**Before reading the key, selecting inputs or building**, the test exclusively creates `funded-self-transfer-receipt.json` with `FileMode.CreateNew` and holds it throughout the attempt. Exactly one concurrent process can win. If a public wallet address is supplied, the read-only collateral-presence preflight runs first and cannot reserve or read a key. The initial public reservation status is then persisted before private-key preflight/build and is updated before submission/after confirmation. Every failure leaves the reservation in place, including an uncertain or incomplete preflight, so automatic replay remains blocked. Never remove it to chase a pass after an uncertain submission. Reconcile the public tx id first. **The reservation lives in `CHRYSALIS_INTEGRATION_OUTPUT`: deleting/cleaning that directory (or its receipt), or choosing a fresh output directory, removes the guard and re-arms one funded attempt.** This is an output-directory-scoped one-shot guard, not a permanent wallet-wide lock. Every invocation still requires fresh explicit `--funded` / `CHRYSALIS_IT_FUNDED=1` opt-in. Do not clean or change it to replay an uncertain attempt. `spend-log.md` records the tx id, transfer and fee; the update-wide 50 test ADA cap must also be checked with the coordinator. The known +44 base-fee discrepancy means the test asserts that the paid fee meets CLI's minimum, not false exact equality.

Node ownership is external to the tests. Obtain the coordinator's approval before starting a shared node and always stop the owned instance gracefully (`docker stop -t 180 NAME`). Never open an existing chain database with a different node version.

## Offline safety regressions

The categorized `FundingSafetyTests` race two reservers without a wallet or submission and verify that an unsuccessful attempt retains its guard. `OracleSafetyTests` rejects matching empty address results, proves bounded retry ordering, and ensures a subject error cannot occur before oracle stability is established. `NarrowSafetyTests` adds pure collateral/provider/body-input checks, missing/invalid collateral handling, portable credential-path checks, loopback discovery/runtime guards and complete datum/script output mutation tests. These remain integration-category cases, not additions to the 1,544-case unit baseline.

`heavy python3 -m unittest discover -s scripts/integration -p 'test_*.py' -v` checks all three active-relay signals, child joining, real shell/cat EOF cleanup, blocked-writer out-of-band cleanup, identity-mismatch refusal and minimal environment/local Docker selection using only synthetic local clients. It also checks that ordinary and include-known wrappers clear inherited funding opt-ins while only `--funded` sets one, preserves a custom package cache, and supports a synthetic dotnet-only PATH without heavy. These Python checks never invoke dotnet, read a wallet or use a real Docker container.
