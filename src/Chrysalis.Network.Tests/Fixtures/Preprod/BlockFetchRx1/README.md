# RX1 public preprod receive fixtures

`manifest.json` records the source Haskell node, capture provenance, original
mux offsets/boundaries, and SHA-256 of every payload. These are public chain/wire
data, not keys, wallet data, or copied node source. No node/container is needed.

The normal regression suite consumes the first six complete BlockFetch bodies
from these unmodified captured payloads. It compares each SHA-256 with the original
capture, and each block's header bytes with those independently sent by the Haskell
node in chain-sync. The first previous-hash is pinned to the range's anchor; each
following Haskell previous-hash independently authenticates the preceding block's
computed hash. Thus the full range has exactly999 node-supplied predecessor
hashes plus the anchor. Header/body hash comparisons are Chrysalis-computed
consistency checks; the last block has no following-header independent hash oracle.
The final captured mux payload also includes part of a later body,
which this small-fixture test intentionally does not request.

For the full 1,000-block offline regression, point
`CHRYSALIS_BLOCKFETCH_RECORDING` at the approved
`work/Chrysalis-perf/benchmarks/out/p1-n2n-recording-a` directory, then run the
network tests through `heavy dotnet test -m:8 -c Release`. Set `NUGET_PACKAGES` to
`work/.nuget/packages`, `DOTNET_CLI_TELEMETRY_OPTOUT=1`, and `DOTNET_NOLOGO=1` first.
The same tests validate the complete recording's SHA manifest before replaying all
original protocol payloads. The no-throw test counts process-wide first-chance
SAIB CborExceptions with other throwing tests excluded from its window.

The hash oracle is the recorded Haskell header/previous-hash chain, not an expected
value generated by this scanner or a serialize/deserialize round trip. The node's
Tip need not be the final block in this historical range; no such equality is
assumed. Raw body bytes are checked before the next receive, retaining today's
borrowed-buffer lifetime contract. The EOF regression completes an already-demuxed
protocol channel only; it does not claim transport-level EOF handling. The known
pre-existing Demuxer truncated-mux EOF defect is phase-2 evidence, not fixed here.
