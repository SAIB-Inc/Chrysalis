# Public Preprod capture fixtures

Captured on **2026-11-15** from **cardano-node 11.1.3**, network **Preprod**, network magic **1**. These are offline golden inputs, not a claim of live coverage against another node version. No service or funded wallet is required to run the tests.

## Provenance and safety

The corpus contains **104 mux-segment payloads**, **10 Conway blocks** (64 transaction bodies), **4 confirmed signed transactions**, and the node's **protocol-parameter JSON**: 119 original public-data files, 162,538 bytes. Every original is copied byte-for-byte; `manifest.json` records its byte count and SHA-256. The fixture-local `.gitattributes` marks CBOR as binary and JSON as `-text` so checkout cannot normalize any hashed original's line endings (including on Windows). The manifest's decoded wire facts were obtained independently with Python cbor2; block header hashes were independently recomputed with BLAKE2b-256. Transaction identifiers, fees and input/output counts are corroborated by recorded cardano-cli output. Expected hashes are constants, not values generated by the codec under test.

Only these allowlisted public artifacts were imported. Blocks, transaction bodies, addresses, public verification keys and signatures are public chain data; protocol frames contain public queries/replies. No mnemonic, signing key, private key, credential, environment file, wallet-generation output or secret directory was imported or read. The four transactions use public signatures and verification keys already submitted to the chain; this directory cannot sign transactions.

## Wire naming and message boundaries

`wire/c<N>-<in|out>-p<P>-<sequence>.cbor` preserves the capture names:

- `c<N>` is the client connection number. `in` is node to client; `out` is client to node.
- `p0` handshake, `p5` node-to-client chain-sync, `p6` local transaction submission, `p7` local state query, `p9` local transaction monitor.
- The sequence is a per-direction segment counter on that connection, beginning at 001. The mux header (timestamp, direction bit, protocol id and payload length) was stripped by the transparent capture proxy; these files are payloads, not complete mux frames.
- `c7-in-p5-004/005/006` are **three fragments of one message**. Their concatenation is a RollForward containing the exact `block-139039741.cbor` bytes.
- **Both** `c4-out-p7-004` (`8105 8107`, query Release + Done) **and** `c5-out-p9-004` (`8103 8100`, monitor Release + Done) contain **two messages**. Therefore 104 segment files represent **104 CBOR messages**, not 103. The tests cover production-channel reassembly and both coalesced-message cases.

Connection scenarios: c1 main Chrysalis N2C probe; c2 separate handshake probe; c3 monitor-release probe; c4 cardano-cli current-era query; c5 cardano-cli has-tx control; c6 state acquire/release; c7 recent-point chain-sync; c8 malformed Chrysalis has-tx; c9 measures probe; c10 rejected empty transaction; c11 direct transfer; c12 Ouroboros-provider transfer; c13 script spend.

Chrysalis proposals offer wire versions 32784–32788 (N2C V16–V20) and negotiate 32788 (V20). The cardano-cli controls offer through 32790 (V22) and negotiate V22. No forced-version matrix was executed in this capture, and **there is no real refusal frame in these 104 files**. Synthetic refusal test vectors are based on the pinned upstream codec, not a node capture. A real wrong-network-magic refusal is not part of this corpus.

Captured protocol edge cases stay authentic and are not silently repaired: inline query results `c1-in-p7-003/005/007/009/011`, inline rejection `c10-in-p6-002`, CLI era-tagged has-tx `c5-out-p9-003`, and 64-bit measures `c1-in-p9-015`, `c9-in-p9-003`. Passing raw-term and integrity checks do not imply typed-decoder support for those shapes. Captured Chrysalis has-tx strings are labelled **legacy malformed requests**, never valid golden encodings.

## Protocol parameters and test scope

`current-protocol-parameters.json` is cardano-cli's node snapshot: protocol **11.0**, 31 top-level fields, fee coefficient **44**, fixed fee **155381**, UTxO byte cost **4310**, memory price **0.0577**, step price **0.0000721**. Its Plutus V1/V2/V3 cost-model lengths are **332/332/350**.

The passing suite loads all 119 originals and checks integrity and independent facts. Working typed message/block/transaction/inner-query decoders are exercised. These tests do not turn raw-term validation into a claim that schema, lifecycle, or unknown-era handling defects are fixed. Raw-preserving comparisons here are **not** fresh re-encoding conformance claims; that is a separate gate. No production sync-path code is modified by these fixtures/tests.
